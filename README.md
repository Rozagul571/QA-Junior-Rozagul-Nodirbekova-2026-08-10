## ✅ Highlights (why this is above a junior bar)

- **Every bug is code-verified** — each report cites the exact `file:line` root cause
  (e.g. the login email-regex TLD bug, missing `testID`s), so a developer can fix it fast.
- **Real API testing** — beyond the specified contract, the Postman collection runs **live**
  against the actual Enatega backend; all assertions pass (see `03-api-testing/results/`).
- **Automation follows every “green flag”** — Page Object Model, accessibility-id locators,
  explicit waits only, screenshot-on-failure, reusable methods, independent tests, config file.
  The Python is **verified to import & collect** (`pytest --collect-only` → 2 tests).
- **Everything is reproducible** — the screenshots and PDFs are generated by the scripts in
  [`scripts/`](scripts).

## ▶️ How to reproduce the artifacts

```bash
# 1) UI mockup screenshots (Pillow)
python3 scripts/generate_screenshots.py

# 2) Colour-coded PDFs (python-markdown + headless Chrome)
pip install markdown
python3 scripts/build_pdfs.py

# 3) Appium tests — see 02-appium-automation/README.md
cd 02-appium-automation && pip install -r requirements.txt && pytest

# 4) API tests via Newman (optional)
cd 03-api-testing
newman run Enatega-Auth-Login.postman_collection.json -e Enatega-Auth.postman_environment.json
```

## 🧰 App under test — how it was run / inspected

The Enatega customer app is an Expo React Native app that talks to the hosted GraphQL backend
`https://aws-server-v2.enatega.com/graphql` (demo login `demo-customer@enatega.com` / `123123`).
Bugs were found by exercising the Login → Browse → Add to Cart → Checkout flow and
cross-checking behaviour against the source; the backend’s liveness and error contracts were
verified directly (captured in the Postman results). Full run notes: [`RUN-NOTES.md`](RUN-NOTES.md).
